# SIMMETRIKA: сайт интернет-магазина диванов (превью)

Превью: https://takedown-desing.github.io/simmetrika-site/ (закрыто от индексации, заявки не уходят менеджеру).
Админка: https://takedown-desing.github.io/simmetrika-site/admin/

Дизайн по референсу из папки `дизайн/` проекта (главная divanchik.ru): раскладка, типографика Roboto, красные кнопки-пилюли, серые подложки товаров, цветные плашки разделов, тёмный блок и подвал. Логотип, фото и тексты референса не использованы. Токены и компоненты описаны в [DESIGN.md](DESIGN.md).

Исследование, структуры страниц и вопросы к заказчику: https://github.com/takedown-desing/simmetrika-prototype

## Админка

`/admin/`: Sveltia CMS 0.250.2 (git-based, формат Decap/Netlify CMS). Все данные сайта лежат в `src/cms/*.json` и правятся только через неё.

| Раздел админки | Файлы | Что меняется |
|---|---|---|
| Товары | `src/cms/products/<категория>--<адрес>.json` | название, адрес, категория, цена «от», размеры, спальное место, механизм, наличие, образцы на распродаже, фото, преимущества, описание, FAQ, SEO |
| Категории каталога | `src/cms/categories/<адрес>.json` | новая категория = страница `/catalog/<адрес>/` с её товарами и пункт в выборе категории у товаров |
| Подборки и фильтры | `src/cms/collections/*.json` | SEO-подборки (ткань, цвет, механизм, «в наличии»…): адрес + правило отбора товаров галочками |
| Страницы | `src/cms/pages/*.json` | главная, каталог, распродажа, доставка, о фабрике, контакты, политика и любые новые страницы |
| Новости и акции | `src/cms/news/*.json` | новость или акция `/news/<адрес>/`, товары по теме |
| Настройки сайта | `src/cms/settings/*.json` | телефоны и реквизиты, доставка, шоурумы с координатами, ткани/цвета/механизмы и коэффициенты цены, меню, ручные переадресации |

У каждой страницы одинаковый SEO-блок: H1, title (счётчик, до 80), description (до 200), og:title/og:description, главный запрос, «Закрыть от индексации» (noindex, follow + исключение из sitemap), canonical, FAQ (идёт в FAQPage).
Текст страницы: markdown со вставками `:::products{rule="…"}`, `:::tiles{items="…"}`, `:::cta`, `:::steps`, `:::form` и др.; шпаргалка в подсказке поля.

**Вход.** «Войти с помощью токена доступа»: GitHub → Settings → Developer settings → Fine-grained tokens → доступ к репозиторию `takedown-desing/simmetrika-site`, право Contents: Read and write. Кнопка «Войти через GitHub» заработает после развёртывания [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth) и `backend.base_url` в `scripts/gen-cms-config.mjs`.

**Публикация.** «Сохранить» делает коммит с `[skip ci]` (сайт не пересобирается на каждую правку). «Опубликовать изменения» шлёт `repository_dispatch: sveltia-cms-publish`, workflow собирает и выкладывает сайт за 2–3 минуты. Кнопка «Открыть на сайте» ведёт на `/go/<коллекция>/<файл>/`, оттуда на итоговый адрес.

**Защита от ошибок.** Три уровня:
1. В форме: обязательные поля, шаблоны адресов (только латиница, `/адрес/`), уникальность адресов, счётчик знаков у title/description. Категории, ткани, цвета, механизмы, шоурумы и товары в новостях выбираются связями (relation) из данных: новая категория или цвет доступны сразу после сохранения, без пересборки. Товар ссылается на категорию по имени файла, поэтому смена адреса категории переносит её товары на новые адреса с переадресациями.
2. Перед сборкой `scripts/validate-cms.mjs`: битый JSON, пустые обязательные поля, неверный адрес, дубль адреса, занятый служебный адрес, значение не из списка, неизвестная или незакрытая вставка `:::`, неверное правило отбора, ссылка на несуществующую страницу (в тексте, плитках, кнопках, меню, «Смотрите также», переадресациях), нет файла картинки, пустой FAQ, поле, не описанное в админке. Любая ошибка останавливает сборку, сайт остаётся прежним; причина в логе GitHub Actions.
3. После сборки: `qa-dist` (H1, meta, JSON-LD, FAQ = FAQPage, ссылки, картинки) и SEO-отчёт `seo-report/index.html` (локально, на сайт не публикуется): длины title/description, дубли, длинное тире, главный запрос не в H1/title, страница без входящих ссылок, подборка меньше 3 товаров, товар без фото или цены. Замечания публикацию не останавливают.

**Пустые поля.** Sveltia сохраняет незаполненные поля пустыми; `src/lib/cms.mjs` отбрасывает их при чтении, поэтому пустые кнопки, плитки и подписи на сайт не попадают. Новая категория или подборка без текста всё равно показывает свои товары (фильтры + сетка по правилу).

**Адреса и переадресации.** Смена адреса, скрытие или удаление записи не дают 404: после сборки `scripts/save-cms-state.mjs` сохраняет карту адресов (`settings/url-map.json`) и накопленные переадресации (`settings/redirects-auto.json`), workflow коммитит их с `[skip ci]`. Следующая сборка создаёт страницы-переадресации (на боевом хостинге 301 по `dist/admin/redirects.txt`), цепочки схлопываются, скрытые и удалённые записи ведут в родительский раздел. Ссылки в текстах на старые адреса при сборке автоматически ведут на новые. Новости ссылаются на товары по имени файла, поэтому смена адреса товара их не ломает.

**Фото.** Загруженные в админке фото лежат в `public/images/uploads/`. Sveltia при загрузке переводит имя в латиницу (`Фото Софы.jpg` → `foto-sofy.webp`) и сжимает в WebP до 1600 px; в CI `scripts/optimize-uploads.mjs` дожимает то, что пришло другим путём. При удалении фото из медиатеки Sveltia убирает ссылку на него из записи.

**Новые подборки и страницы.** Раздел сам показывает ссылки-чипы на вложенные подборки (`/catalog/x/` → `/catalog/x/y/`), если текст раздела на них ещё не ссылается; хлебные крошки новых страниц строятся по адресу. Категория с галочкой «Показывать в меню», которой нет в «Меню сайта», сама дописывается в конец первой колонки меню «Каталог товаров». Пустой title заменяется на «H1 | SIMMETRIKA».

## Проверки

```bash
npm ci
npm run validate     # конфиг админки + проверка данных
npm run build        # prebuild: конфиг и проверка; postbuild: карта адресов, переадресации, SEO-отчёт
npm run qa           # проверка собранного dist
npm run test:admin   # сквозной тест админки на временной копии, 117 проверок
```

`test:admin` повторяет работу редактора, записывая JSON так же, как Sveltia (все поля, пустые значения): правка title и цены товара, новая страница с FAQ и кнопкой, новая категория с товаром без фото и цены (сама попадает в меню «Каталог товаров»), подборка без title (в `<title>` «H1 | SIMMETRIKA»), новость с блоком «Товары по теме», две подборки по правилам, пункт меню, телефон, смена адреса товара дважды (переадресации и схлопывание цепочки), скрытие и возврат товара, удаление новости, боевой режим `PREVIEW=0` (robots, canonical, noindex, sitemap), 26 типичных ошибок редактора (в том числе повтор или кириллица в коде цвета, удалённый цвет, который ещё используется, образец без шоурума), каждая должна остановить сборку с понятным сообщением. `config.yml` проверяется по официальной JSON-схеме Sveltia той же версии. В GitHub Actions тест запускается при изменении кода (push), при публикации из админки нет.

## Что внутри

| Путь | Что это |
|---|---|
| `src/cms/` | данные сайта (правятся в админке) |
| `src/lib/cms.mjs` | слой данных: каталог, страницы, адреса, переадресации |
| `src/lib/md.mjs`, `src/lib/render.mjs` | markdown и вставки `:::` → HTML; карточки, плитки, шоурумы, формы, схемы |
| `src/lib/schema.mjs` | JSON-LD @graph: Organization+FurnitureStore, WebSite, тип страницы, BreadcrumbList, Product+AggregateOffer, FAQPage |
| `src/pages/index.astro`, `src/pages/[...slug].astro` | главная; все остальные страницы |
| `src/pages/go/`, `src/pages/cms-state.json.js` | служебное для админки |
| `public/admin/index.html` | админка; `config.yml` генерирует `scripts/gen-cms-config.mjs` (в git не хранится) |
| `public/js/app.js` | заявка в localStorage, фильтры, выбор ткани/цвета/стороны с пересчётом цены и URL-параметрами, галерея, формы |
| `scripts/` | `gen-cms-config`, `validate-cms`, `save-cms-state`, `optimize-uploads`, `test-admin`, `qa-dist`, `links-audit`, `compare-dist`, `build-images` |

## Ограничения превью

- Заявки сохраняются только в браузере (нет бэкенда): номер заявки и экран «спасибо» работают, письмо менеджеру не уходит.
- Цены, сроки, тарифы, ткани и гарантия: рабочие допущения до ответов клиента (`QUESTIONS.md` в репозитории проекта).
- Фото стоят как есть. Задача «одинаковый фон у всех фото» требует обтравки и делается отдельно.
- Превью целиком закрыто от индексации (`PREVIEW` не задан). Для боевого домена: `PREVIEW=0`, правильный `SITE.origin`/`base` в `src/lib/site.mjs`, 301 из `dist/admin/redirects.txt`.
